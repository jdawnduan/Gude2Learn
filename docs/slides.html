See It, Say It, Pick It

One photo of a robot workcell and one English sentence become a safe robot action: a plan, a question, or a refusal.

The idea in one sentence: the smallest Apertus (8B, 4-bit, text-only) writes every answer, while an open vision model lists the objects and plain Python turns boxes into a scene table with geometry hints, so the whole pipeline runs locally on a 5 GB GPU and reproduces with one command.

Pipeline · which model does what

Six steps, one model writes the answer

In: photo 2448×2048 px + one instruction, e.g. "put the red gear under the yellow gear in the grey tray" Out: target_pixel + pick/place steps, or one question, or one refusal
1 · vision model

See

qwen3.5 9B lists every object with a box; a second call asks only about stacking, trays and the machine parts. Cached per scene.

→
2 · python

Table

Boxes become pixels; duplicates numbered in reading order; tray and support per object; machine parts relabelled by box size; pixel moved onto the object by colour.

→
3 · python

Resolve

Noun phrases matched to the table, spatial cues (left, closest to, in the grey tray, under) evaluated on coordinates. Written as reference hints plus unsafe / unknown / unpickable flags.

→
4 · apertus

Plan

Reads table and hints with a fixed decision order: unsafe, not there, cannot, ambiguous, plan. Decides plan / ask / refuse. Output constrained to a per-scene schema.

→
5 · apertus, ≤ 3×

Self-check

Only when the answer contradicts a hint fact (asks with one match, refuses a listed object, plans an unsafe verb, picks the bottom of a stack, moves an excluded object, drops the destination). The message names the correction; Apertus answers again.

→
6 · python

Render

Steps expanded to the submission format; a set-aside becomes a place on the table. In questions and reasons every internal name becomes a description a person can act on, built from the same geometry.

Apertus v1.5 8B text-only: community Q4_K_M GGUF (hf.co/Colby) of the swiss-ai weights, in Ollama, 5 GB open vision model, sees only Python, no model

Apertus writes every answer, Python keeps it on the rails

Plan, ask or refuse is always parsed from an Apertus reply; Python's two fallbacks never fired in the 90 answers. But the hints name the resolved object and the rule that applies, and a check message names the correction. Measured: first replies alone 50.4 / 65, no hints 48.8, with hints and check rounds 65.0.

Python does geometry, rules and rendering

Counting matches, left/right/closest, what lies on what, which tray, what is excluded, where things go: computed from coordinates and written into the prompt as hints, so Apertus does not have to do arithmetic.

Constrained decoding, per-scene schema

The grammar admits pick/place steps only over the names in this scene, or exactly one question, or exactly one refusal. No malformed answers, no invented objects.

Lessons learned · limits and what we would do next

Built on the minimal model on purpose

What we chose, and why

  • Apertus v1.5 8B, Q4_K_M, text-only (the smallest Apertus, 5 GB) does all language reasoning; qwen3.5 9B only lists objects with boxes.
  • Runs on a 5 GB Quadro P2200 + 32 GB RAM Windows box, a 16 GB M2 Mac, and a Linux aarch64 box (dev set in 638 s there; about 25 min on the P2200).
  • Lesson: a small model decides well when counting, geometry and the answer grammar are taken off its plate, and when it is shown its own contradiction instead of a correct example.
  • One command reproduces: uv run python run.py --data heldout --out results_heldout.json

Expected gains with stronger models

  • Apertus 70B or a larger quantisation: fewer self-check rounds, better multi-step plans, no copying of examples, reasons stated without being quoted the fact.
  • Stronger or larger vision model: no confusion of the three machine parts, reliable stacking without the physical prior and box-overlap fallback, tighter boxes.
  • Untested options: Apertus "think" mode (--think is wired, not evaluated), higher vision resolution than 1024 px.

Known limits

  • Non-determinism, vision side: four full runs (Windows committed, Linux box three times, Windows fresh): three score 63.4, all on "pick up the object lying on the grey part", because the vision model drew the grey part and the small part of that scene as one box. The committed 65.0 is the one run where it drew them apart; the other 14 tables agree within a few pixels. A part-reference fallback now resolves the merged table: fresh Windows tables 65.0, and a fresh Linux run of the final code 65.0; the committed answers are unchanged by it. The committed files are a --reuse re-render (31 of 90 re-asked after the review).
  • Held-out: pixels cannot be checked locally, only the answer types (32/32 plans, 8/8 no-plan, from the published labels). The resolver's synonyms and cues were extended on the published held-out wording after its release (disclosed in README and report): weaker evidence than a blind run.
  • Black tray missing from the vision table in 7 of 15 scenes; unsafe detection is a keyword list; refusal labels sometimes wrong.
